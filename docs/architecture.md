# 架构

> 交付视图：只写「现在的形状与不变量」。设计推演、备选方案与逐条取舍见
> 分层推演、领域模型、存储与事件、工作区划分、并发与背压这几份设计推演原文
> **本机留档、不入库**；本文件是交付视图，只写结论与取舍。

## 0. 一句话

**Tauri 2 外壳 + 单个 Rust 守护进程**：外壳只负责窗口、托盘、daemon 生命周期
与打包；一切采集、理解、存储、检索都在 `mc-daemon` 里，渲染层通过本机 HTTP +
SSE 与它说话。数据全在本机。渲染层是纯 `vite` 构建的静态产物，外壳与渲染层
之间只有一条约定：`runtime.json`（端口 + token）。

## 1. 进程与分层

```
Tauri 外壳（src-tauri/，独立 crate）   mc-daemon（唯一后端）
  ├─ 拉起 mc-daemon ───────────────▶ 加载配置 → 开库 → 绑 127.0.0.1 → 写 runtime.json
  ├─ 托盘 / 窗口 / 单实例锁 / 自启        ├─ 控制面（axum 路由 + SSE）
  └─ 初始化脚本：注入 mcRuntime          ├─ 采集环（独立循环）
                                          ├─ 投影 + 活动推断（独立循环）
渲染层（React，纯 vite 产物）               ├─ 语义索引（独立循环）
  └─ 适配层：把渠道调用改成 HTTP/SSE ─────▶ └─ 保留策略（独立循环）
```

**四个循环互不阻塞**是硬约束：模型慢、限流、掉线都不会让采集停摆；
采集只负责产出观测，绝不等待分析。

crate 分层（依赖只能向下，`check-source.sh` 里的依赖方向守卫把关）：

| 层 | crate | 职责 |
|---|---|---|
| 0 | `mc-common` | 时间（UTC 毫秒 `Timestamp`）、错误分类（错误码 + 组件 + 可重试 + 补救）、日志出口与脱敏 |
| 1 | `mc-config` / `mc-domain` | 配置加载与迁移；领域模型与纯状态机（活动规则、阶段、投影的函数部分） |
| 2 | `mc-storage` / `mc-providers` / `mc-capture` / `mc-mcp` | SQLite 与迁移、blob 与保留策略；模型 provider（只依赖 HTTP 抽象与 OpenAI 兼容的接口形状）；采集源抽象；MCP 客户端（stdio/HTTP、权限闸门） |
| 3 | `mc-pipeline` / `mc-summary` / `mc-search` / `mc-memory` | 采集环与分级调度、预算闸门；总结生成（模型 + 确定性兜底）；检索（关键词 + 向量融合）；笔记树归档与实体 |
| 4 | `mc-server` | 控制面：路由、信封、SSE、后台任务的接线；编排 MCP 与 Chat tool loop |
| 5 | `mc-daemon` / `mc-cli` | 进程入口；运维命令（doctor / 配置校验 / 导入 / 重放） |
| 工具 | `mc-testkit` / `apps/xtask` | 测试夹具与脚本化替身；契约夹具生成 |

## 2. 数据流与事件溯源

```
采集 ──▶ Observation（不可变） ──▶ 投影 ──▶ Activity ──▶ Stage ──▶ Summary
         │                            │
         └─ 变化检测 / 隐私拦截       └─ 规则命中 / 模型推断（带来源与置信度）
```

- **事件是唯一真源**：`events` 与 `observations` 只追加；活动 / 阶段 / 总结都是
  **派生数据**，随时可重建 —— 改算法不需要迁移历史，重放即可。
- **投影是全量纯函数**：同样的输入永远得到同样的输出，因此投影可以幂等重跑；
  `derived_from_seq` 记录「这一行是从哪个事件位点算出来的」。
- **用户修正先作为事件落库，再重算派生表**：顺序不能反 —— 直接改派生表的话，
  下次重放就丢了用户的修改。
- 写入放大被刻意摊平：不是「每来一条观测就重放整段历史」，而是定时 + 变更检测
  触发投影（`check-summary-invariant.sh` 守着阶段总结的不变量）。

## 3. 领域模型要点

- **Activity 才是核心**：Observation 是「屏幕/窗口上发生了什么」，Activity 是
  「这段时间在做什么」；Stage 把连续活动收成一段工作，Summary 是它的产物。
- **来源可区分**：每个活动带 `Provenance`（`observed` 直接来自窗口/进程名 /
  `rule` 命中用户规则 / `inferred` 模型推断，含模型名）与置信度；界面据此标注，
  用户可改名（改名走事件）。
- **规则优先于模型**：用户写的规则（`rules/activities.yaml`）命中时**一次模型都不调**，
  这是省 token 的主要手段；规则没判出来的活动才进入四道闸门（规则已判 → 预算 →
  同窗口复用 → 滑动窗口限流）。
- **总结一定有**：模型不可用时用确定性兜底，但质量标记（`model` / `fallback`）
  必须显示出来 —— 兜底和模型总结看起来一样，用户就分不清值不值得信。

## 4. 存储与保留

- **SQLite 单写者**：所有写入经 `with_write` 串行化、读取走 `with_read`；
  多个进程各开句柄 + pragma 不一致会引入跨进程锁竞争，单写者从结构上排除它。
- **数据库只存路径与哈希，图片落文件系统**：两者混在一起会让磁盘与 DB 一起失控，
  清理策略也无从下手。blob 是**内容寻址**（文件名即内容哈希，天然去重）。
- **兼容层列形状与被替换的契约逐列一致**：笔记树、活动列表这些调用方直接消费
  返回值，改一个字段就是空界面。
- **保留策略**：按天数 / 总字节 / 条目数轮转，**删文件的同时清掉数据库引用**
  （只删文件留破图，只清引用则磁盘泄漏）；被拦下的观测不参与检索。
- **作业表带租约**：单条 `UPDATE ... RETURNING` 完成「挑一个 + 占用」，
  多个 worker 并发也不会拿到同一条；崩溃由租约回收兜底，启动时把未收尾的阶段
  补记为「被中断」。

## 5. 采集、隐私与成本

- **采集源可插拔**：`screen` / `window` 已实现；`clipboard` / `file` / `browser`
  已在类型与配置里预留，配置点名时启动日志会**如实报告「尚未实现」**，
  绝不悄悄退回「截全部屏幕」。
- **先便宜后昂贵**：像素级变化检测 → 廉价元数据（进程名 / 窗口标题）→ 规则 →
  才轮到模型；没变化的帧不落盘也不落库。
- **隐私是路径上的关卡**：拦截在落盘之前（命中黑名单的观测与同轮屏幕帧一起拦），
  脱敏在出网之前（本地记录不受影响）；两者分开，做错位置会损失本地信息。
- **成本有上界**：预算按滑动窗口限制**调用次数与 token**（超限降级为只用廉价
  元数据，活动照常产出），每次调用的 token、耗时与结果都进 `provider_calls`，
  被闸门拦下的调用也留痕（原因写进 `error_code`）。

## 6. 并发与背压

- 采集环、投影/推断、语义索引、保留策略各跑各的循环；模型调用走 `TaskClass`
  分池（视觉 / 总结各自容量），图片积压不会把总结饿死。
- 队列压力分档（正常 → 合并冗余画面 → 只分析重大变化 → 丢弃），
  **过载时降频，绝不丢观测**：写不进去的观测留在待写队列。
- 失败重试 + 指数退避 + 终态记录；单条失败不阻塞整轮，采集循环**绝不退出**。

## 7. 可观测性

- 统一日志出口 `mc-common::observability`：每条日志带 `component` 与 `event`，
  支持 `MC_LOG` 调级、文件落盘与轮转；**不写内容、密钥、路径**（守卫把关）。
- 每个错误都带错误码、组件、严重级别、是否可重试与补救建议；
  失败落 `pipeline_failures`，`/api/v1/diagnostics/export` 能导出可分享的诊断包。
- 诊断接口暴露待分析队列长度、失败分布、保留策略执行结果与预算状态 ——
  「采集在跑但没产出」这类问题必须能一眼看出来。

## 8. 几个刻意的取舍

| 取舍 | 为什么 |
|---|---|
| 事件溯源 + 全量重投影，而不是就地更新 | 派生表可以丢；算法升级后旧数据仍能重算，用户的修正不会在重放中丢失 |
| 单写者 SQLite，而不是多进程共享 | 跨进程 pragma 与锁竞争是最难查的一类问题，从结构上排除它 |
| 图片落文件系统 | 数据库里塞二进制会让备份、清理与体积一起失控 |
| 提示词编译进二进制 | 模板缺失或用户改坏都不该让分析整体停摆（升级后「分析持续失败」的经典成因） |
| provider 只依赖 HTTP 抽象 | 不绑厂商 SDK；向量维度从响应推断，换模型不会静默错位 |
| 时间只有 UTC 毫秒一种表示 | naive 与 aware 混用是后台定时任务最经典的事故源 |
| 只保留一条桌面外壳（Tauri 2），外壳与渲染层之间只有 `runtime.json` 一条约定 | 两条外壳意味着每个能力都要在两处实现并各自验证；Tauri 的依赖树不进根 workspace（`src-tauri/` 是独立 crate），因此不拖慢后端门禁。渲染层与外壳通过端口/token 解耦，换外壳不动业务代码 |
