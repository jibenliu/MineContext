# 采集节奏：空闲降频与锁屏暂停

## 背景

长时间按正常间隔截图会浪费磁盘与电量。用户离开（无输入）或锁屏时，采集应降频或暂停。

## 决策

两套独立门控，**锁屏优先**：

| 条件 | 行为 | 配置 |
|---|---|---|
| 屏幕已锁定 | **硬暂停**：本 tick 零帧，解锁后恢复（不补采） | 当前始终开启；可配置开关由锁屏暂停能力另行提供 |
| 未锁定，且空闲 ≥ 阈值 | **降频**：间隔改为 `idle_interval_secs` | `capture.idle_threshold_secs`（默认 300）、`capture.idle_interval_secs`（默认 60） |
| 未锁定，且未达空闲阈值 | 正常间隔 `interval_secs` | `capture.interval_secs`（默认 15） |

探测失败时按「未锁定 / 不空闲」处理：宁可多采，也不因探测失败整体停采或误降频。

## 组合

- 同时锁屏且空闲 → 只走锁屏硬暂停，**不会**按空闲间隔继续采。
- 解锁后若仍空闲 → 立刻适用空闲降频，而不是先打一顿正常频率再降。
- `idle_interval_secs` 生效时不会快于 `interval_secs`（配置层夹紧）。

## 为什么分开

空闲是「人还在会话里但没操作」——仍可能需要粗粒度记录（例如开会时屏幕静止）。锁屏是「会话已离开桌面」——锁屏画面本身是隐私，应硬停。把两者揉成单一「backoff 档位」会在锁屏时仍落盘无意义帧。
